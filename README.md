# eqcorrect — 周波数特性 (振幅・位相) 補正エンジン

生の音声 (.wav) と測定ファイル (.req) から補正用の逆フィルタを設計し、**周波数領域の高速畳み込み**で補正済み .wav と
可視化用の解析データ (JSON) を出力します。可視化は C++ 本体から**完全に分離**した HTML/JS (依存ライブラリなし) です。

```
 .wav (A) ─┐                               ┌─ 補正済み .wav
           ├─ eqcorrect (C++) ─────────────┤
 .req ─────┘  逆フィルタ設計 → FFT 畳み込み  └─ result.json / result.js ─→ web/index.html (ブラウザ)
```

## 構成

| パス | 内容 |
|---|---|
| `src/main.cpp` | CLI 本体 (引数処理・全体の流れ・JSON 出力) |
| `src/fft.hpp` | 自前 FFT (radix-2, double, AVX2 intrinsics 対応) |
| `src/wav.hpp` | WAV 読み書き (PCM 8/16/24/32, float 32/64, EXTENSIBLE, チャンネルマスクの保持) |
| `src/channels.hpp` | チャンネル名の解決 (WAV の配置 / ファイル名 / 別名) |
| `src/req.hpp`, `src/javaser.hpp` | .req ローダー (テキスト / Java シリアライズ / インパルス応答) |
| `src/design.hpp` | 逆フィルタ設計、オーバーラップ加算の畳み込み (チャンネルごとに別フィルタ可) |
| `src/analysis.hpp` | Welch スペクトル・伝達関数推定・波形エンベロープ |
| `web/` | ビューア (`index.html`, `chart.js` 自前 Canvas グラフ, `app.js`, `style.css`) |
| `tools/` | `serve.py` (簡易サーバー), テストデータ生成・検証スクリプト |
| `tests/`, `run_tests.sh` | 回帰テスト一式 |

## ビルド

外部ライブラリは不要です (単一翻訳単位)。C++17。

```sh
make                 # Linux / macOS / MSYS2 : AVX2 版 (g++)
make AVX2=0          # AVX2 を使わない版 (古い CPU 用)
CXX=clang++ make     # clang++ も可
```
Windows: `build_msvc.bat` (x64 Native Tools プロンプトで。`/utf-8` が必須) または `build_mingw.bat`。
**注意: Windows 側 (MSVC / MinGW / 日本語パス) は、この README を作成した環境 (Linux) では実行確認できていません。**
Linux で g++ / clang++ (AVX2 あり・なし) の 3 通りが警告なしでビルドでき、出力がビット単位で一致することは確認済みです。

## 使い方

```sh
./eqcorrect raw.wav measurement.req -o corrected.wav -j web/result.json
python3 tools/serve.py            # → ブラウザが開き、result.json を自動表示 (下記「ビューア」参照)
```

主なオプション (全一覧は `./eqcorrect --help`):

| オプション | 既定 | 説明 |
|---|---|---|
| `--taps N` | 65536 | 補正フィルタ長 = FFT サイズ (2 のべき乗, 1024〜)。48 kHz で周波数分解能 0.73 Hz |
| `--phase M` | full | `full` 測定位相を逆に / `min` 最小位相 / `linear` 位相補正なし |
| `--max-boost` / `--max-cut` | 12 / 24 dB | 補正量の上限 |
| `--ref-band LO,HI`, `--no-normalize` | 500,2000 Hz | 基準レベル (この帯域の平均を 0 dB に) |
| `--smooth N` | なし | 測定を 1/N oct 平滑化してから逆特性化 |
| `--edge-oct X` | 0.5 | 測定範囲の端で**振幅の**補正量を 0 に収束させる幅 |
| `--fmin` / `--fmax` | 測定範囲 | 補正する帯域を制限 |
| `--window W` | tukey | 補正 IR の窓: `tukey` `bh` `hann` `none` |
| `--remove-delay` | しない | 測定位相の純遅延成分を補正対象から除く |
| `--bits B` | same | `same` `16` `24` `32` `f32` |
| `--dither D` | auto | auto = 16 bit 出力時のみ TPDF ディザ |
| `--gain-db G`, `--protect-clip` | 0 / なし | 出力ゲイン / 0 dBFS 超過時に自動で下げる |
| `--save-filter F` | — | 設計した補正フィルタを float32 モノラル WAV で保存 |
| `--req-role R` | auto | REW のEQフィルタの扱い: `correction` (そのEQを適用; auto はこれ) / `measurement` (合成応答を測定とみなし逆特性化) |
| `--dump-req`, `--dump-full` | — | .req の構造を表示して終了 (`--dump-full` は配列を全要素) |

## マルチチャンネル (チャンネルごとの .req)

```sh
./eqcorrect movie51.wav eq_folder/                       # フォルダ内の *.req を全部使う
./eqcorrect movie51.wav null_EQ_L.req null_EQ_R.req null_EQ_C.req null_EQ_LFE.req null_EQ_Lrs.req null_EQ_Rrs.req
./eqcorrect movie51.wav L=a.req R=b.req C=c.req           # チャンネルを明示 (ファイル名に依存しない)
./eqcorrect stereo.wav one.req                            # .req 1 つ → 全チャンネルに同じ補正 (従来どおり)
```

**どの .req がどのチャンネルか**: ファイル名 (拡張子を除く) を `_ - . 空白` などで区切り、**末尾側から順に**見て最初にチャンネル名として読めるトークンを採用します
(`null_EQ_C.req` → C、`room-Lrs.req` → Lrs)。読めない場合は推測せずエラーにします (`NAME=ファイル` で指定)。
同じチャンネルに 2 つ割り当たる場合もエラーです。

**チャンネル名** (大文字小文字は区別しません): `L R C LFE` / `Lss Rss` (サイド) / `Lrs Rrs` (リア) / `Lc Rc` / `Cs` (リアセンター) / `Tfl Tfc Tfr Tc Tbl Tbc Tbr` (ハイト)。
別名: `FL FR FC`, `SW`/`Sub`, `Ls Rs` (= サイド), `BL BR`/`RL RR` (= リア), `Left`/`Right`/`Center` など。

**WAV 側のチャンネル順**: ① `--channels L,R,C,LFE,Lrs,Rrs` の指定 → ② WAVEXTENSIBLE のチャンネルマスク (ビット数 = チャンネル数のとき) → ③ チャンネル数からの標準配置を仮定
(1=C, 2=L R, 3=L R C, 4=L R Lrs Rrs, 5=L R C Lrs Rrs, 6=L R C LFE Lrs Rrs, 7=L R C LFE Cs Lss Rss, 8=L R C LFE Lrs Rrs Lss Rss)。どれを使ったかは実行ログに出ます。
それ以外のチャンネル数でマスクも無い場合は `--channels` が必須です。

**サラウンドの読み替え**: WAV にサイド系 (Lss/Rss) が無くリア系 (Lrs/Rrs) だけある (5.1 など) とき、`Ls`/`Rs` の .req はリアへ、逆にリア系しか無い .req でサイドだけの配置ならサイドへ割り当てます (ログに通知)。
7.1 のように両方ある配置では読み替えません (`Ls`/`Rs` = サイド)。

| オプション | 既定 | 説明 |
|---|---|---|
| `--channels LIST` | 自動 | WAV のチャンネル順を指定 |
| `--missing M` | passthrough | .req が無いチャンネル: `passthrough` = 補正せずそのまま出力 / `error` |
| `--ignore-extra` | しない | WAV に無いチャンネルの .req を無視 (しないとエラー。フォルダ指定のときは常に無視して通知) |

注意:
* **チャンネルごとに独立に設計**し、同じオプション (`--taps`, `--phase`, `--max-boost` …) を全チャンネルに適用します (チャンネル別の個別設定はありません)。
* 測定データの .req は**チャンネルごとに基準レベル (既定 500–2000 Hz) を 0 dB に正規化**するため、チャンネル間のレベル差は補正されず、保たれもしません (各チャンネルの基準帯域レベルが入力と同じになるだけ)。
  チャンネル間レベルの調整が必要なら `--no-normalize` か別途ゲインで行ってください。REW のEQフィルタ (そのまま適用) では正規化しないので、設定どおりのゲインが掛かります。
* 同じ .req を複数チャンネルに使うと、設計は 1 回にまとまります。
* 出力 WAV には入力のチャンネルマスクを保持します。`--save-filter F` は `F_<チャンネル名>.wav` として保存します。
* 解析データ (スペクトル・波形・統計) は先頭 16 ch までです。ビューアではチャンネル選択欄で切り替えます (補正なしのチャンネルは「素通し」と表示)。
* JSON の構造が変わりました: 設計ごとの値は `designs[]`、チャンネルの割り当ては `channel_info[]` にあります (ビューアは旧形式の JSON も読めます)。

## アルゴリズム

1. **逆フィルタ設計** (`design.hpp`): 測定 H(f) を対数周波数軸で補間 (振幅は dB、位相は巻き戻した連続値)。
   基準帯域の平均レベル L0 を引いて正規化し、補正量 `C_dB = −(H_dB − L0)` (上下限でクリップ)、
   位相 `C_φ = −H_φ` とする (`--phase full`)。IFFT で時間領域の補正 IR c[n] を得て窓を掛ける。
   因果化のため c[n] に N/2 サンプルの遅延を付加する (周波数領域では `(−1)^k` の乗算)。
2. **周波数領域畳み込み** (`Convolver`): 入力 A をブロックに分け `FFT(A)·FFT(C)` → IFFT → オーバーラップ加算。
   `FFT(C)` は 1 回だけ計算。C が実数であることを使い、**2 チャンネルを実部・虚部に詰めて 1 回の FFT で処理**する。
   複素乗算 = 「振幅の dB 加算 + 位相の減算」。付加遅延は出力時に差し引くので、出力は入力と時間が揃う。
3. **解析データ**: 補正前後の Welch スペクトル、実測の伝達関数 H=Gxy/Gxx (振幅・位相)、設計値との比較、波形エンベロープ、IR。

## .req ファイルについて (重要)

`.req` には**2種類の意味**があり、中身で自動判別します。

| 種類 | 意味 | 処理 |
|---|---|---|
| **REW のEQフィルタ** (Java シリアライズ, `roomeqwizard.Filter` の配列) | 適用する**EQそのもの** (パラメトリックEQ) | そのEQを補正として**そのまま適用** (既定)。`--req-role measurement` なら合成応答を測定とみなして逆特性化 |
| 測定データ (テキスト / Java 配列 / インパルス応答 など) | 補正対象の**周波数特性** | 逆フィルタを設計して補正 |

### REW のEQフィルタ (実ファイル `null_EQ_C.req` で確認済み)

* ファイル先頭は `TMreq Filters File:Equaliser:Generic`、続いて 28 スロットの `roomeqwizard.Filter`。未使用スロットは種別 `NONE`。
* 実ファイルは **PK (ピーキング) 5 個**のみ有効 (57.5 / 86.5 / 142 / 277 / 10769 Hz, −3.7〜−11.3 dB)。
* 保存されているバイクアッド係数は RBJ ピーキング式と倍精度で一致することを確認済み (相対差 −317 dB)。
  WAV の fs が保存 fs (48000 Hz) と同じなら保存係数をそのまま、違えば fc/ゲイン/Q から RBJ 式で再計算します
  (**REW が他の fs でも同じ式で再計算するかは未確認**)。
* バイクアッドは最小位相なので、位相も含めてそのまま再現され、**プリリンギングはありません**。
  EQ をそのまま忠実に再現するため、基準レベル正規化・ブースト/カット上限・端のテーパは**適用しません**。
* **確認できているのは PK のみ**です。LS/HS/LP/HP 等が有効だと、推測で計算せず**エラーで止まります**
  (`--dump-full` の出力か該当ファイルをいただければ対応を追加できます)。無効 (`enabled=false`) と `NONE` は無視します。

### 測定データの形式 (自動判別)

| 形式 | 判別 | 内容 |
|---|---|---|
| Java シリアライズ | 先頭 `AC ED 00 05` | `double[]`/`float[]`/`ArrayList<Double>`/`double[][]`/オブジェクトのリスト/HashMap から数値列を抽出 |
| テキスト | 上記以外で印字可能 | `周波数[Hz] 振幅[dB] (位相[deg])`。区切りは空白/タブ/`,`/`;`。`#` `*` `;` 始まりや見出し行は無視。UTF-8/UTF-16 |
| IR テキスト | 1 列のテキスト | インパルス応答 (`--req-format ir-text` なら 2 列目を値に) |
| 生バイナリ | `--req-format raw-f32` / `raw-f64` | リトルエンディアンのインパルス応答 |

**Java 測定データの割り当て方針**: 配列・フィールド名から周波数 (`freq/hz/…`・単調増加)、振幅 (`gain/mag/db/…`)、位相 (`phase/deg/…`) を決めます。
**名前から決められない場合は推測せずエラーにし、候補一覧を表示します。** その場合は:

```sh
./eqcorrect --dump-req 測定.req                         # 構造を確認 (クラス名・フィールド名・配列の長さ/範囲)
./eqcorrect --dump-full 測定.req                        # 配列を全要素表示 (数値は 17 桁)
./eqcorrect raw.wav 測定.req --java-map "freq=クラス.フィールド,mag=クラス.フィールド,phase=クラス.フィールド"
```
単位は `--req-mag-unit db|linear`, `--req-phase-unit deg|rad`。位相が無い場合は振幅から最小位相を推定します。

## ビューア

3 通りの開き方があります。

1. **サーバー経由 (推奨)**: `python3 tools/serve.py [--data 出力フォルダ]` — `result.json` を自動読み込み、補正前後 WAV の A/B 試聴も自動。
2. **ファイルを直接開く**: `web/index.html` をダブルクリック。`web/result.js` があれば自動表示 (CLI は `.json` と同名の `.js` も出力します)。
   なければ JSON/JS ファイルをウィンドウへドロップ。
3. 任意の場所の `result.json` をドロップ。

マルチチャンネルでは上部の「チャンネル」欄で切り替えます (名前つき。条件タブの割り当て表の行クリックでも切替)。

タブ: 補正特性 (振幅/位相) / 補正前後スペクトルと実測伝達関数 / 補正フィルタ IR / 波形 / 条件・試聴・ログ。
ドラッグで範囲拡大、ダブルクリックでリセット、Ctrl+ホイール、←→キー、凡例クリックで表示切替、各グラフに「表で見る」と CSV。
ライト/ダークは OS 設定に追従し、右上で切替可能。配色は検証済みパレット (補正前=橙, 補正後=青, 補正量=アクア)。

## 設計上の既定値 (作成時に私が選んだもの — すべて変更可能)

| 項目 | 既定 | 理由・影響 |
|---|---|---|
| FFT | 自前 radix-2 (+AVX2) | 外部ライブラリ不要で配布が楽。FFTW より遅い |
| 基準レベル正規化 | 500–2000 Hz を 0 dB | 出力の基準帯域レベルが入力と同じになる (全体が大きく変わらない) |
| 補正量の上限 | +12 / −24 dB | 測定の深いノッチを無理に持ち上げない |
| 測定範囲の外 | 補正しない | 外は情報がないため。端 0.5 oct は振幅補正を滑らかに 0 へ |
| 位相のテーパ | **かけない** | 端の位相は数百度に達しうるため (振幅だけテーパ。上端は最終値保持、下端は DC の 0 へ接続) |
| 窓 | Tukey (外側 25%×2 の Hann) | IR の打ち切りによる周波数特性の乱れを抑える |
| 付加遅延 | taps/2 を出力で打ち消し | 全位相補正は非因果成分 (プリリンギング) を持つため |
| 補間 | 対数周波数軸の線形補間 | 測定が対数間隔であることを想定 |
| 出力形式 | 入力と同じ | 8 bit→16 bit、float64→float32 に変換。16 bit は TPDF ディザ |
| クリップ | 警告のみ | 勝手にゲインを変えない (`--protect-clip` で自動) |
| 出力ファイル | `.json` と `.js` の 2 つ | `.js` は file:// で直接開く用 |
| REW のEQフィルタの扱い | そのEQを補正として適用 | REW のフィルタファイルは「補正用のEQ」なので。測定の逆にしたい場合は `--req-role measurement` |
| 追加機能 | `--save-filter`, `--dump-req/--dump-full`, `--java-map`, `--req-role` | 検証・調査用に追加 |
| グラフ | Chart.js ではなく自前 Canvas | CDN/ネットワーク不要・オフラインで動作 |

## 検証結果 (Linux / g++ 13, 2 vCPU)

* **既知の劣化を与えて復元** (8 段のバイクアッド縦続: 振幅 −7〜+6 dB と位相回転を持つ特性を音声に与え、その特性を .req として渡す):
  補正帯域内で元音声との SNR が **−3.8 dB → 52〜56 dB**。テキスト・Java 6 種 (配列/ArrayList/オブジェクト列/ラッパー/HashMap/2 次元配列) は同一精度。
  インパルス応答 .req は 45〜53 dB。位相なし .req / `--phase min` / `linear` は振幅偏差 7.75 dB → 0.05 dB 以下。
* **REW のEQフィルタ (実ファイル)**: 保存係数の IIR (scipy `sosfilt`, 倍精度) との差 **−152 dB** (float32 出力の精度限界)。44.1 kHz (RBJ 再計算) も同等。
* **畳み込みの独立検証**: numpy `fftconvolve` との最大差 ≈ 3e-8 (フィルタ長 1024〜262144, 1〜5000 サンプル, 3ch, 各位相方式)。
* **マルチチャンネル**: 6ch でチャンネルごとに別の EQ を適用した結果が、(a) 独立計算の IIR (scipy `sosfilt`) と最大差 2e-10 (32 bit PCM の量子化限界)、(b) 各チャンネルを単独で処理した結果とビット単位で一致。
  5.1/7.1/マスク無し/`--channels`/サイド↔リア読み替え/素通し/各種エラー (判定不能・重複・存在しないチャンネル) と、日本語のフォルダ名を `tests/test_multichannel.py` で検証。
* 入出力: PCM 8/16/24/32・float 32/64、1/3/6 ch、極端に短いファイル、壊れた WAV/.req、日本語ファイル名。
* **ファジング** (ASan+UBSan): 壊れた Java データ/WAV/テキスト/実 REW ファイル 約 11000 件 (マルチチャンネルの壊れたマスク/チャンネル名指定を含む)。これで 2 件の実バグを発見・修正済み (ヘッダ計算の整数オーバーフロー、チャンネル数破損時のバッファ外読み出し)。
* **性能**: 10 分ステレオ 48 kHz/24 bit (173 MB) で畳み込み約 4 秒 (65536 taps)、全体 8〜11 秒。
  **AVX2 は、この環境では非 AVX2 版と速度差が測れませんでした** (出力は完全に同一)。お使いの CPU では異なる可能性があります。

`./run_tests.sh` で再現できます (numpy/scipy 必須、java・node+playwright があれば Java 形式とビューアも検証)。

## 既知の制限

* **実物の .req で確認できたのは REW のフィルタファイル (PK のみ) 1 件**です。測定データ形式 (周波数/dB/位相) の実物と、REW の他のフィルタ種別 (LS/HS/LP/HP 等) は未確認です。
* Windows (MSVC/MinGW、Windows 上の日本語パス) は未実行です。
* シミュレーションによる検証のみです。実機の測定では、測定ノイズや大きなノッチ (上限で制限される) のため残差は大きくなります。
* メモリ使用量は概算で `16 byte × サンプル数 × ch` (10 分ステレオで約 0.9 GB)。4 GB を超える WAV (RF64) は非対応。
* マルチチャンネルは、全チャンネルのデータを 2 組 (入力/出力) メモリに持ちます。**概算で 16 byte × サンプル数 × ch** (6ch・10 分・48 kHz で約 2.8 GB)。
* チャンネル別の個別オプション (チャンネルごとに別の `--phase` など) や、チャンネル間レベルの自動調整はありません。
* マルチチャンネルの実ファイルは、ご提供の `null_EQ_C.req` 1 件しか確認できていません。L/R/LFE/Lrs/Rrs 等は同形式の自作ファイルによる検証です。
* `--phase full` はプリリンギングを生みます。気になる場合は `--phase min` を使ってください。
* 測定位相に大きな純遅延が含まれる場合は `--remove-delay` を使ってください (フィルタ長の半分を超える先送りは折り返します)。
* AVX-512 / インラインアセンブリは実装していません (AVX2 intrinsics のみ)。
* カンマ小数点 (`1,5`) のテキストには対応していません (カンマは区切りとして扱います)。
